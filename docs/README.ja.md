## はじめに

> [!IMPORTANT]
>
> 現在の `Wishes` はまだテスト段階にあり、一部の機能は不完全です。

`Wishes` は、汎用的で高度にカスタマイズ可能なガチャシミュレーターです。
*タグシステム* を通じてすべてのカード、デッキ、バナー、ガチャロジックを統一的に管理し、*組み合わせ可能なロジックエンジン* を活用することで、**ほぼあらゆる** ゲームのガチャ体験を自由にシミュレートできます。

> 実はゲームに限りません。あなたが望むなら、`Wishes` は **ほぼあらゆる** ランダムシステムをシミュレートできます。

すべてのデータは **ローカル** に保存されます。**読み取り専用ソース** (公式 / 拡張パック) のデータに対するユーザーの編集は、常に **ローカルコピーを派生** させ、元のデータは決して書き換えられません。これが **データ分岐モデル** です。

各バナーのランタイム状態 (天井カウンターなど) は `SQLite` に永続化され、**状態スコープ** をキーとします。デフォルトでは各バナーが独立して状態を維持しますが、複数のバナーで同一の状態を共有することもできます (バナー間での天井の引き継ぎなど)。

## v0.2.0 重要な更新

> [!WARNING]
>
> **今回のアップデートには、データフォーマットの非互換な変更が含まれています**。ローダーは起動時にデータディレクトリ直下の `version.json` を読み取り、バージョンを検証します。バージョンが一致しない場合は即座に失敗し、**自動マイグレーションは行いません**。アップグレードの際は、v2 形式に従ってデータディレクトリを再構成してください。

- **データフォーマット v2**
  - すべてのコアオブジェクト (カード / デッキ / ロジック / バナー) は、一意の識別子として `GlobalId` (Uuid v7) を統一的に使用するようになり、以前のバージョンの自動採番整数 Id に代わります。
  - ユーザー向けのテキストフィールド (カード内容、デッキ名、バナー名、ロジック名) は **多言語マップ** (言語タグ → テキスト) として保存され、フロントエンドが現在の UI 言語に応じてフォールバック解決します。
  - 各オブジェクトは **ソース** マーカーを持ちます: `official` (公式)、`local` (ローカル)、`pack:<name>` (拡張パック)。
  - データは **ソースごとに物理的に分離** されています: `data/official/` と `data/packs/<name>/` は読み取り専用、`data/local/` は書き込み可能です。

- **データ分岐モデル**
  - 読み取り専用ソースのオブジェクトを編集する場合、その場で書き換えるのではなく、**ローカルコピーを派生** させます (新しい `GlobalId`、`origin = local`、`forked_from` が元のオブジェクトを指す)。
  - 派生オブジェクトは、元のオブジェクトを **遮蔽** するかどうかを選択できます。遮蔽時は元のオブジェクトが一覧やガチャのクエリから隠され、デッキ内の参照はローカルオーバーレイ (SQLite。公式ファイルは書き換えられません) を通じて派生オブジェクトへリダイレクトされます。遮蔽を解除すると、参照は元のオブジェクトへ解決されます。現在、カードは遮蔽の手動切り替えに対応していますが、デッキの対応 UI は後続のリリースで追加されます。
  - 派生オブジェクトを削除すると、元のオブジェクトは自動的に再表示されます。

- **状態スコープ**
  - バナーのランタイム状態を保存するキーが「バナー Id」から「スコープキー」に変更されました:
    - `banner:<uuid>` (デフォルト): 各バナーが独立した状態を維持します。
    - `group:<name>`: 同じグループ内の複数のバナーが単一の状態を共有します (バナー間での天井の引き継ぎなど)。
  - **旧データベースとは非互換** です。v1 時代のテーブル構造が検出された場合、起動時に再構築され、以前の天井の進捗は失われます。

- **その他**
  - ローダーは、ソースを跨いだ `GlobalId` の一意性検証、およびバナーが参照するデッキ / ロジックの存在性検証を新たに実行します。

## クイックスタート

### インストーラーのダウンロード

一般ユーザーは、ビルド済みのインストーラーから `Wishes` をすぐに体験できます。

[**Releases**](https://github.com/wishes-gacha/wishes/releases) ページにアクセスし、お使いのプラットフォーム用の最新インストーラーをダウンロードしてください。

ダウンロード後は通常どおりインストールして起動するだけです。初回起動時に、内蔵のデフォルトカード、デッキ、ロジック、バナーデータがユーザーデータディレクトリにコピーされます。

### ソースからのビルド

自身でコンパイルしたい方、ソースコードを変更したい方、開発に参加したい方向けです。

#### 動作環境

- [**Node.js**](https://nodejs.org/) ≥ 18
- [**Rust**](https://www.rust-lang.org/tools/install) (*stable*)
- お使いのプラットフォームに対応した [**Tauri 2 のシステム依存関係**](https://tauri.app/start/prerequisites/)

#### 開発モード

```bash
# フロントエンドの依存関係をインストール
npm install

# npm を使用して開発サーバーを起動
npm run tauri dev
# または cargo を使用
# cargo run tauri
```

> [!NOTE]
> 
> 開発モードでは、アプリケーションはプロジェクトルートの `data/` と `db/` を優先的に読み込みます。データファイルを変更した後は再起動すると反映されます。

#### リリース版のビルド

```bash
# npm を使用
npm run tauri build
# または cargo を使用
# cargo tauri build
```

ビルド成果物は `src-tauri/target/release/bundle` に出力され、プラットフォームごとに対応する形式のファイルが生成されます。
